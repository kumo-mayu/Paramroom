# paramroom

VRChat のアバターに、**PC の画像や QR コードを送って見せる**ギミックです。

VRC+ の Prints と違って **VRChat の中で撮った写真に限りません**。PC にある画像ファイルや、ブラウザから
ドラッグしてきた画像、URL から取ってきた画像を、そのまま相手に見せられます。ワールド側の対応も要りません。

アバターの**同期パラメータ（Int を最大 32 個 = 256 bit）だけ**を使い、画像を図形の並びに置き換えて
100 ms ごとに少しずつ送ります。受け取る側のアバターがそれを絵に描き直します。

- **画像**：10〜20 秒でだいたい分かる絵になり、100 秒ほどで全部揃います
- **QR コード**：**Int 32 個なら 1 秒かかりません**。かかる時間は Int の数と URL の長さで変わるので
  （少ない Int では十数秒になることもあります）、下の表を見てください。送信アプリが、選んだ
  アバターでの実際の秒数を表示します。相手はスマートフォンの標準カメラアプリで、鏡越しでも
  そのまま読めます（実機で確認済み）

## 先に知っておいてほしいこと

できないこと・向かないことがあります。導入前に確認してください。

- **相手からは、フレンドか「Show Avatar」を押した人にしか見えません。** アバター上のカメラがリモートで
  動く条件がそれだからです。
- **PC 専用です。Quest / Android では動きません**（カメラもカスタムシェーダーも無効になります）。
- **同期パラメータを最大 32 Int（256 bit）使います。** アバターの空きに収まる数を選んでください
  （少ない Int でも動きますが、そのぶん 1 周が長くなります）。画像をあきらめて QR コードだけにするなら
  **Int 3 個**から使えます（下の「QR 専用」）。
- **画像は 100 秒ほどかかります。** 会話の合間にさっと見せる用途には向きません（QR コードなら数秒です）。
- **相手が「遠すぎる」「表示人数制限」でこちらを隠している間は進みません。** 表示に戻れば描き直されます。
- **同じアバター（同じ blueprint ID）を 2 人以上が着ていると絵が壊れます。** VRChat がカメラループの
  RenderTexture をアバター単位で共有するためです。**これを組み込んだアバターをそのまま配るのは
  お勧めしません**（各自が自分のアバターに入れてアップロードする形なら問題ありません）。
- **絵は粗くなります。** 写真そのままではなく、図形を重ねた近似です。

## 利用上の注意

送信する画像について、必要な著作権その他の権利・許諾を確認して使用してください。第三者の権利を侵害する画像や、
VRChat の [Terms of Service](https://hello.vrchat.com/legal) /
[Community Guidelines](https://hello.vrchat.com/community-guidelines) /
[Creator Guidelines](https://hello.vrchat.com/creator-guidelines) に反するコンテンツの送信には使用しないでください。

## 必要なもの

| もの | 備考 |
|---|---|
| Unity ＋ VRChat SDK (Avatars) | アバターをアップロードできる環境。動作確認は Unity 2022.3.22f1 / SDK 3.10.4 |
| [Modular Avatar](https://modular-avatar.nadena.dev/) | プレハブを置くだけでパラメータとアニメーターが入ります。1.17.1 で確認 |
| アバターの同期パラメータの空き | **Int 32 個（256 bit）**が理想。少ない数でも動きます |
| Windows PC | 送信アプリを動かすため。配布している exe は .NET を同梱しているので、別途入れる必要はありません |
| VRChat の OSC が有効 | 送信アプリがアバターのパラメータを動かすのに使います |

## ダウンロード

[Releases](https://github.com/kumo-mayu/Paramroom/releases) から 2 つ取ってください。

| ファイル | 何に使うか |
|---|---|
| `Paramroom-unity-*.unitypackage` | アバターに入れる部品。Unity のプロジェクトにインポートする |
| `Paramroom.App.exe` | 画像を送るアプリ。置いた場所から直接起動できます（インストール不要） |

exe に電子署名はしていません。初回起動時に Windows の SmartScreen が
「WindowsによってPCが保護されました」と出ることがあります。**詳細情報** →
**実行** で起動できます。気になる場合は、このリポジトリをそのままビルドしてください
（`dotnet publish tools/Paramroom.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true`）。

## 入れかた

1. Releases の最新版から `Paramroom-unity-*.unitypackage` をプロジェクトにインポートする
   （`Assets/kumo-mayu/Paramroom` に入ります）。リポジトリから使う場合は
   `measure/unity/Assets/kumo-mayu` を `Assets/` にコピーしても同じです。
2. ヒエラルキーでアバター（またはその子）を選ぶ。
3. **Tools/Paramroom/Decoder Builder** を開く。アバターの同期ビットの空きが表示されるので、
   収まる Int 数を選んで作る（**迷ったら形式 3 ＋ 32 Int**）。
4. できた `Assets/kumo-mayu/Paramroom/ParamroomDecoder*.prefab` をアバターの直下に置く。
5. 表示板（`Display`）を見せたい位置・大きさに動かす。
6. アバターをアップロードする。

### 選べる形式と Int の数

Int は 1〜32 のどれでもよいわけではなく、**1 パケットに入る図形の数が変わる数だけ**が選べます
（同じ図形数なら、Int を増やしても遅くなるだけなので出していません）。ビルダーが下の一覧を出し、
アバターの空きに収まらないものは選べなくなります。

| 形式 | キャンバス / 図形数 | 選べる Int と、画像 1 周にかかる時間 |
|---|---|---|
| **3（標準）** | 512px / 4000 | 10 (400秒)・18 (200秒)・25 (133秒)・**32 (100秒)** |
| 4（軽量） | 512px / 4000 | 9 (400秒)・15 (200秒)・21 (133秒)・26 (100秒)・**32 (80秒)** |
| 5（軽量・図形多め） | 512px / 5000 | 9 (500秒)・15 (250秒)・21 (167秒)・27 (125秒)・**32 (100秒)** |
| 6（実験用） | 1024px / 4000 | 11 (400秒)・18 (200秒)・25 (133秒)・**32 (100秒)** |

- **迷ったら形式 3 ＋ 32 Int。**
- **軽量（形式 4・5）**は座標と色の精度を少し落とす代わりに 1 パケットに図形を多く詰めます。
  見た目の差はほとんどありません（`measure/results/2026-09-17/precision`）。空きが少ないアバターや、
  速さを優先したいときに向きます。
- **形式 6（1024px）は VRChat での負荷を測るために用意したもので、常用は勧めません。**
- **QR コードの時間は上の表とは別**で、Int が多いほど速くなります。

| Int | 25×25（短い URL） | 37×37（長めの URL） |
|---:|---:|---:|
| 9〜11 | 1.2〜1.5 秒 | 2.5〜3.1 秒 |
| 15〜18 | 0.6〜0.8 秒 | 1.3〜1.6 秒 |
| 21〜25 | 0.4〜0.5 秒 | 0.9〜1.1 秒 |
| 26〜32 | 0.3〜0.4 秒 | 0.7〜0.8 秒 |

### QR 専用（Int 3 個から）

**同期パラメータがほとんど空いていないアバター向け**に、QR コードだけを出すデコーダーも作れます。
ビルダーの「QR 専用」タブから選んでください。**画像は出せません。**

上の形式が Int 9〜10 個を下限にしているのは QR の都合ではなく、**画像用の割り付け（1 パケットに
図形 1 個が入ること）を QR モードでも使い回しているから**です。QR だけと割り切ればその制約が無くなります。

| Int | 短い URL（25×25） | 長め（37×37） | 最大（57×57） |
|---:|---:|---:|---:|
| 3 | 3.2 秒 | 8.5 秒 | 21.9 秒 |
| **4** | **2.0 秒** | 5.4 秒 | 14.0 秒 |
| 6 | 1.2 秒 | 3.1 秒 | 7.9 秒 |
| 8 | 0.8 秒 | 2.2 秒 | 5.5 秒 |
| 16 | 0.4 秒 | 1.0 秒 | 2.6 秒 |

- **迷ったら 4 Int。** 32 bit だけで、短い URL が 2 秒で出ます
- 表示板の作りも軽くなります（512×512 のキャンバスを持たず、升目ぶんのテクセルだけ）
- 出せるのは **57×57（版 10）まで**です。長すぎる URL は短縮してください

詳しくは [`measure/unity/Assets/kumo-mayu/Paramroom/README.md`](measure/unity/Assets/kumo-mayu/Paramroom/README.md) を見てください。

## 使いかた

1. VRChat を起動し、上のアバターに着替える。
2. 送信アプリを起動する。アバターは自動で見つかります（VRChat を後から起動しても大丈夫です）。
3. 画像を指定する：**ファイルを選ぶ**／**URL を入れる**／**ブラウザや エクスプローラーからドラッグ**／
   **Ctrl+V で貼り付け**のどれでも。
4. 文字列を QR コードにしたいときは、QR の欄に入れて「QR コードにする」。
5. 「送信を始める」。相手のアバターに少しずつ絵が出ます。

**人が多い場所では送信の間隔を伸ばしてください**（アプリで変えられます）。混んでいるとパケットを
取りこぼしやすく、100 ms のままだと逆に遅くなります。

**相手のフレームレートが低いときも間隔を伸ばしてください。** 受け取る側は「同じ値が 2 フレーム続いた」
ことを確かめてから取り込みます（壊れた値を弾くため）。既定の 100 ms だと **30 fps あれば問題なく、
20 fps で少し取りこぼし、10 fps ではほとんど届きません**。200 ms にすれば 15 fps でも届きます。
なお**絵が壊れることはありません**。遅くなるだけです。

## 仕組み（簡単に）

画像をそのまま送るには 256 bit は狭すぎるので、**画像を「色のついた楕円 4000 個」に置き換えて**送ります。
楕円は「絵の狂いが大きく減る順」に選ばれるので、**途中まででも意味の分かる絵**になります。1 パケットは
それ自体で完結していて、順番も取りこぼしも気にしません。

QR コードのときは、白黒の升目そのものをパケットに載せます（画像として送るより 40〜100 倍速い）。

設計と実測の記録は `docs/` にあります。
