# ImagePad（アバターに入れる部品）

VRChat の同期パラメータ（Int）だけを使って、静止画を周りの人に送るための受信側です。送信は PC 側のアプリ（`tools/ImagePad.App`）が行います。

## 先に知っておくこと（導入できるかの条件）

- **相手からは、フレンドか「Show Avatar」を押した人にしか見えません**。アバター上の Camera がリモートで動く条件がそれだからです（`docs/research/01-vrchat-parameters.md`）。
- **Quest / Android では動きません**。Camera もカスタムシェーダーも無効になります。PC 専用です。
- **同期パラメータを最大 32 Int（256 bit）使います**。アバターの空きビット数に収まる Int 数を選んでください（ビルダーがアバターの空きを表示します）。
- **アバターを読み込み直されると絵は消えます**（相手が再参加した、Show Avatar を押し直した等）。送り続けていれば 1 周で戻ります。
- **相手がこちらを「遠すぎる」「表示人数制限」で隠している間は、絵が進みません**。表示に戻ると読み込み直しになるので、
  そこから 10〜20 秒で見られる程度に戻り、1 周（既定 100 秒）で全部揃います。
  人の多いワールドでは、**見せたい相手に近づいてもらう**のが確実です。
- **同じアバター（同じ blueprint ID）を 2 人以上が着ていると、絵が壊れます**。カメラループの RenderTexture をアバター ID 単位で共有してしまうためです（VRChat 側の仕様）。配布アバターにそのまま入れる場合は、着る人ごとに別アップロードが必要です。
- シェーダーを許可していない相手（セーフティ）には、表示板ごと見えません。

### 送る画像について

**送った画像は、その場にいる人に見えます。** 自分で撮った写真や自分で描いた絵、あるいは使ってよいと
分かっているものだけにしてください。他人の画像・漫画・ゲーム画面などをそのまま見せると、
著作権の問題になることがあります（公開の場で見せる＝公衆送信にあたりえます）。

このギミックは画像を粗くしますが、**粗くすれば問題が無くなるわけではありません**。

## 送れるもの：画像と QR コード

**どの形式のプレハブでも、画像と QR コードの両方を出せます**。どちらを出すかは送信アプリ側で決めるので、
プレハブを作り直す必要はありません。

| | 画像 | QR コード |
|---|---|---|
| 揃うまでの時間 | 100 秒ほど（10〜20 秒でだいたい分かる絵になる） | **1 秒かからない**（例: 25×25 升で 3 パケット = 0.3 秒） |
| 用途 | 写真・イラスト・資料 | URL などの文字列 |
| 相手が隠していた場合 | 表示に戻ってから 1 周（100 秒） | 表示に戻ってすぐ |

QR コードは、白黒の升目そのものをパケットに載せています（画像として送ると 12〜27 秒かかりますが、
升目として送れば 0.3 秒で済みます。`docs/research/09-qr-code.md`）。

## 作れる形式

図形 1 個のビット数：形式 3 は 58 bit、軽量（形式 4/5）は 47 bit（座標 8・半径 6・角度 5・色 444・α 2）、形式 6 は 59 bit。

| `ImagePad_Format` | 内容 | 選べる Int の数（1 周の時間、100 ms/パケット） |
|---|---|---|
| **3** | **512px・図形 4000 個（これを使う）** | 10（400 s）/ 18（200 s）/ 25（133 s）/ **32（100 s）** |
| 4 | 512px・図形 4000 個・軽量 | 9（400 s）/ 15（200 s）/ 21（133 s）/ 26（100 s）/ 32（80 s） |
| 5 | 512px・図形 5000 個・軽量 | 9（500 s）/ 15（250 s）/ 21（167 s）/ 27（125 s）/ 32（100 s） |
| 6 | 1024px・図形 4000 個（**実験用**。下の注意を読むこと） | 11（400 s）/ 18（200 s）/ 25（133 s）/ 32（100 s） |

- **迷ったら形式 3 ＋ 32 Int**。1 周 100 秒で、10〜20 秒でだいたい分かる絵になります。
- 軽量（4/5）は序盤の見え方が少し速い代わりに、線画や文字の最終的な画質がわずかに落ちます。
- **形式 1（256/1000）と 2（512/2000）**：もう作りません（2026-09-17）。既にそれを入れたアバターには送信側からそのまま送れます。
- 形式の比較：`measure/results/2026-09-17/precision`、`comparison-4`、`measure/results/2026-09-18/repr`。

## 入れかた

1. この `ImagePad` フォルダをアバターのプロジェクトの `Assets/ImagePad` に入れる。
2. ヒエラルキーでアバター（またはその子）を選ぶ。ビルダーが空きビット数を表示します。
3. **Tools/ImagePad/Prim Decoder Builder** を開き、形式と Int の数を選んで作る。
4. できた `Assets/ImagePad/ImagePadPrimDecoder*.prefab` をアバターの直下に置く。
5. 表示板（`Display`）を見せたい位置・大きさに動かす。
6. アバターをアップロードする。
7. PC 側で送信アプリを起動すると、アバターを自動で見つけて送り始めます。

## 中身

| 場所 | 中身 |
|---|---|
| `Editor/ImagePadPrimBuilder.cs` | **Tools/ImagePad/Prim Decoder Builder** のウィンドウ。形式と Int の数を選び、`Assets/ImagePad/ImagePadPrimDecoder*.prefab` を作る |
| `Editor/ImagePadModularAvatar.cs` | Modular Avatar のコンポーネントを付ける共通の処理（測定用のビルダーも使う） |
| `Shaders/ImagePadPrimDecoder.shader` | カメラループで図形を描き直すデコーダー |
| `Shaders/ImagePadPrimDisplay.shader` | 表示板（縦横比に合わせて形を変える） |

プレハブは Modular Avatar の Merge Animator と Parameters を使います。同期パラメータは `KUMO_ImagePad_D0`..`KUMO_ImagePad_D(n-1)`（Int）、それに加えて `KUMO_ImagePad_Format`（**同期しない**ローカル専用の Int。送信側が形式を知るために使う）を登録します。

- 名前に `KUMO_ImagePad_` を付けているのは、他のギミックとの衝突を避けるためです（パラメータ名は同期されないので、長くても 256 bit の枠は使いません）。
- **2026-09-18 より前に作ったプレハブは `D0`.. という名前**です。送信アプリは両方を自動で判別するので、そのままでも送れます。
- Write Defaults は ON で作ります（単一レイヤーの Direct Blend Tree のため）。アバター全体を OFF で統一している場合は VRChat の警告が出ます。

## 形式 6（1024px）についての注意

1024 は「近づいて見たときに文字が読めるか」を上げるための候補ですが、**VRChat での負荷を測るために用意したもので、採用は決めていません**（`docs/research/08-primitive-representation-experiments.md` §17）。通常は形式 3 を選んでください。

- 図形 1 個は **59 bit**（座標 10・半径 8・**角度 5**・色 565・α 2）。座標に 10 bit 要るので角度を 1 bit 削り、パケットに縦横比コード用の 8 bit を残している
- **アトラスが 2048x1044 になる**（512 のときは 1024x536）。ARGBHalf なので **1 枚 16.3 MB、2 枚で約 33 MB の VRAM**（512 は合計 9 MB）。VRChat の Texture Memory の評価に算入される場合、ランクが下がる可能性があります（未確認）
- **1 パス（= 1 フレーム）の画素数が約 4 倍**になる。1 周（4000 図形）に要するパス数は 512 と同じ 126 なので、**フレーム当たりの負荷が約 4 倍**という見積もり
- シミュレーション上は、**元画像を大きく縮小して送る場合（ページ全体のスクリーンショットなど）にしか利点がありません**。切り出した画像では 512 のほうが良い結果でした
- 重すぎる場合は、ビルダーの `Format.batch`（1 パスで描く図形数、既定 32）を下げてから作り直すと、フレーム当たりが軽くなる代わりに 1 周のフレーム数が増えます。**生成済みのマテリアルを手で書き換えるときは A/B 両方を同じ値にしてください**（食い違うと絵が完成しません）

## 測定用の道具との分け方

同期の遅れや取りこぼしを測る表示板とそのビルダー、デコーダーの自動テスト（`ImagePadPrimTest`）とテストデータは `Assets/ImagePadMeasure` に置いています。アバターに入れるのは `Assets/ImagePad` だけでよいです。

## 前の配置（Assets/ImagePadMeasure に全部あった版）から移すとき

1. アバターのプロジェクトの `Assets/ImagePadMeasure` から、`Editor/ImagePadPrimBuilder.cs`、`Shaders/ImagePadPrimDecoder.shader`、`Shaders/ImagePadPrimDisplay.shader` を消す。残すと同じクラスやシェーダーが 2 つになり、コンパイルエラーやシェーダーの取り違えが起きる。
2. この `ImagePad` フォルダを `Assets/ImagePad` として入れる。
3. ビルダーでプレハブを作り直し、アバターの古い `ImagePadPrimDecoder*` と入れ替える。古いプレハブと `GeneratedPrim*` フォルダは、消したシェーダーを指しているので消してよい。
